# Structures DST - notes for Claude Code

A UK highway-structures decision support tool (SAMPT method, SAVI v1.10-compatible): WGA valuation, 5-year
programme and long-term plan, with grounded AI features. MVP stage. **Task for this repo now: deploy the MVP**
following `DEPLOY.md` (route A, Vercel, unless the user picks another).

## Layout
- `src/dst_engine/`: Python reference engine (verified against SAVI). `tests/`: pytest (data, unit, property, regression, ui).
- `web/`: browser app. `src/engine/` is the TypeScript port of the engine, `src/ui/` is React, `build.mjs` is the bundler.
- `deploy/`: what gets deployed. `public/index.html` is generated by `web/build.mjs`; do not edit it by hand.
- `docs/DECISION_LOG.md`: why things are the way they are (D-001...). Read before changing behaviour.

## Commands
```bash
cd web && npm ci && npm run typecheck && npm test && node build.mjs   # 31 engine/service/AI tests, then build
cd deploy && npm test                                                # AI proxy unit tests
pip install -e ".[test]" pytest-cov pytest-playwright && pytest      # full suite incl. Playwright UI tests
```

## Rules
- Never change engine numbers without the SAVI regression tests passing (`tests/regression`, `web/test/engine.test.ts`).
- The deployment MUST set both `ANTHROPIC_API_KEY` and `DST_ACCESS_CODE` (6+ characters) in the host's environment
  settings. Ask the user to paste the key into the host's own prompt (e.g. `vercel env add ANTHROPIC_API_KEY production`),
  and never echo, log, commit or write it to a file. Ask the user which access code they want, or offer to generate one.
- The server fails closed: without both values the AI stays off. Do not weaken this.
- After deploying, run `cd deploy && node verify.mjs <url>` (all checks must PASS), then the browser checklist in
  `DEPLOY.md`. Report the URL and the check results; give the access code only to the user.
